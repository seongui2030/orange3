### 2. 오렌지3 위젯 연결 및 군집화 실행 절차

| 단계            | 사용 위젯 (카테고리)            | 위젯 연결 방법 (포트 연결)                                                   | 구체적 설정 및 조작 방법                                                                                                                                                                       | 확인 기준 (정상 작동 여부)                                                                 |
| :-------------- | :------------------------------ | :--------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------- |
| **1단계** | `File`*(Data)*              | 캔버스에 단독 배치                                                           | 위젯을 더블클릭 후 폴더 아이콘을 눌러 `evcharging_2.csv` 선택 → 하단 `Columns`에서 `latitude`, `longitude`의 `Type`이 `numeric`, `Role`이 `feature`인지 확인 후 창 닫기       | 창 좌측 하단에 `99`가 표시됨                                                             |
| **2단계** | `Data Table`*(Data)*        | `File` 오른쪽 출력(반원) → `Data Table` 왼쪽 입력(반원) 드래그          | 두 위젯 간 회색 실선이 생기도록 간격을 띄워 연결한 뒤, `Data Table`을 더블클릭하여 원본 좌표 데이터 확인                                                                                     | 상단에 `99 instances`와 2개 열(`latitude`, `longitude`) 표 출력                      |
| **3단계** | `k-Means`*(Unsupervised)*   | `File` 오른쪽 출력 → `k-Means` 왼쪽 입력 드래그                         | 위젯 더블클릭 → `Number of Clusters`에서 **Fixed** 선택 후 `3`(실루엣 점수 최고 `0.5844`) 또는 `4` 입력 → `Initialization`은 **k-Means++** 유지 (창 닫기 시 자동 실행) | `k-Means` 창 하단에 실루엣 점수(Silhouette score)가 계산되어 표시됨                      |
| **4단계** | `Data Table (1)`*(Data)*    | `k-Means` 오른쪽 출력(`Annotated Data`) → 새 `Data Table` 입력 드래그 | 군집 번호가 부여된 결과를 확인하기 위해 위젯을 더블클릭하여 열 구성 확인                                                                                                                       | 기존 위도·경도 열 옆에 `Cluster`(`C1`, `C2`, `C3`) 및 `Silhouette` 열 추가 확인 |
| **5단계** | `Scatter Plot`*(Visualize)* | `k-Means` 오른쪽 출력 → `Scatter Plot` 왼쪽 입력 드래그                 | 위젯 더블클릭 → **Axis X:** `longitude`, **Axis Y:** `latitude` 선택 → 좌측 속성 패널의 **Color:** 항목을 `Cluster`로 지정                                           | 2차원 평면 위에 3개 군집(`C1~C3`)이 서로 다른 색상 점으로 구분되어 표시됨                |
| **6단계** | `Save Data`*(Data)*         | `k-Means` 오른쪽 출력 → `Save Data` 왼쪽 입력 드래그                    | 위젯 더블클릭 → `Determine type from the file extension` 체크 확인 → **Save as...** 클릭 후 파일명을 `evcharging_cluster.csv`로 입력하여 저장                                      | 지정 경로에 군집 라벨(`Cluster`)이 포함된 `.csv` 파일 생성 완료                        |

### 3. 전체 워크플로 연결 구조 요약

```text
[ File (evcharging_2.csv) ] ──┬──> [ Data Table ] (원본 데이터 99행 확인)
                              │
                              └──> [ k-Means (k=４) ] ──┬──> [ Data Table (1) ] (군집 번호·실루엣 점수 확인)
                                                       ├──> [ Scatter Plot ]   (위도·경도 군집 시각화)
                                                       └──> [ Save Data ]      (결과 CSV 내보내기)

> 💡 **실전 팁**
> * 군집 개수를 **4개**로 확정해 분석하려면 `Fixed: 4`로 두고 진행하시면 되며, **99개 데이터 전체에 `C1~C4` 중 하나의 군집 번호가 빠짐없이 붙습니다.**
> * 만약 일부 외곽 데이터는 군집에 억지로 넣지 않고 **이상치(Outlier / 노이즈)**로 따로 구분하고 싶다면 K-Means 대신 **DBSCAN** 같은 밀도 기반 군집화를 사용해야 합니다.

## 오렌지3(Orange3)를 이용한 타이타닉 생존 유무 이진 분류 절차 (`Titanic.csv`)

`Titanic.csv`는 총 **891개 데이터(승객)**와 **12개 변수**로 구성되어 있으며, 이 중 **`Survived`** (`0`: 사망 549명, `1`: 생존 342명)를 **타깃(Target)** 으로 설정해 생존 여부를 예측하는 이진 분류 워크플로를 구성합니다.

### 1. 데이터셋 컬럼 및 결측치 요약

| 컬럼명 | 데이터 타입 | 결측치 수 | 역할 설정 권장 |
| :--- | :--- | :---: | :--- |
| `PassengerId` | 정수(`int64`) | 0 | **Skip** (단순 식별자) |
| `Survived` | 정수(`int64`, 고유값 2개) | 0 | **Target** (이진 분류 정답) |
| `Pclass` | 정수(`int64`, 고유값 3개) | 0 | **Feature** (객실 등급) |
| `Name` | 문자열(`object`) | 0 | **Skip** 또는 **Meta** |
| `Sex` | 문자열(`object`, 고유값 2개) | 0 | **Feature** (성별) |
| `Age` | 실수(`float64`) | 177 | **Feature** (나이, 결측치 존재) |
| `SibSp` | 정수(`int64`) | 0 | **Feature** (동반 형제·배우자 수) |
| `Parch` | 정수(`int64`) | 0 | **Feature** (동반 부모·자녀 수) |
| `Ticket` | 문자열(`object`) | 0 | **Skip** (고유값 많아 일반화 불리) |
| `Fare` | 실수(`float64`) | 0 | **Feature** (운임 요금) |
| `Cabin` | 문자열(`object`) | 687 | **Skip** (결측치 비율이 높음) |
| `Embarked` | 문자열(`object`, 고유값 3개) | 2 | **Feature** (승선 항구) |

---

### 2. 오렌지3 캔버스 워크플로 구성 순서

1. **데이터 불러오기 (`File`)**
   - 캔버스에 **File** 위젯을 추가하고 `Titanic.csv`를 엽니다.
   - `Survived` 열의 **Role**을 **Target**으로 지정합니다(`0`/`1` 이진 분류 타깃으로 인식되는지 확인).
   - `PassengerId`, `Ticket`, `Cabin`은 **Skip**으로 설정하고, `Name`은 필요 시 **Meta** 또는 **Skip**으로 둡니다.
   - `Pclass`, `Sex`, `Age`, `SibSp`, `Parch`, `Fare`, `Embarked`는 **Feature**로 둡니다.

2. **결측치 처리 및 전처리 (`Impute` / `Select Columns`)**
   - `Age`(결측치 177개)와 `Embarked`(결측치 2개)에 결측치가 있으므로, **File** 뒤에 **Impute** 위젯을 연결해 결측치를 평균/중앙값(수치형) 또는 최빈값(범주형)으로 대체합니다.
   - 필요에 따라 **Select Columns** 위젯을 추가해 예측에 사용할 Feature와 Target을 한 번 더 점검합니다.

3. **이진 분류 모델 위젯 연결 (`Logistic Regression`, `Random Forest`, `Tree` 등)**
   - 전처리된 데이터 출력(`Data`)을 분류 알고리즘 위젯들에 연결합니다.
   - 기본 이진 분류 비교를 위해 **Logistic Regression**, **Random Forest**, **Naive Bayes** 등을 캔버스에 배치합니다.

4. **모델 성능 평가 (`Test & Score`)**
   - 전처리된 데이터(`Data`)를 **Test & Score** 위젯의 `Data` 입력에 연결하고, 각 분류 모델 위젯의 출력(`Learner`)을 **Test & Score**의 `Learners` 입력에 연결합니다.
   - **Test & Score** 왼쪽에서 **Cross validation**(예: `Folds: 10`) 또는 **Random sampling**을 선택하고 **AUC**, **CA**(분류 정확도), **F1**, **Precision**, **Recall** 지표를 비교합니다.

5. **오차 행렬 및 ROC 곡선 확인 (`Confusion Matrix`, `ROC Analysis`)**
   - **Test & Score**의 출력을 **Confusion Matrix**에 연결해 실제 생존(`1`)/사망(`0`) 대비 예측 결과를 행렬로 확인합니다.
   - **ROC Analysis**를 연결해 모델별 ROC 곡선과 AUC 성능을 시각적으로 비교합니다.

6. **새 데이터/테스트 데이터 생존 예측 (`Predictions`)**
   - 예측 대상 승객 데이터(`Survived`가 비어 있거나 `?`로 된 CSV/XLSX)를 별도 **File** 위젯으로 불러와 **Predictions** 위젯의 `Data`에 연결합니다.
   - 학습된 모델의 출력을 **Predictions** 위젯에 연결하면 승객별 예측 클래스(`0` 또는 `1`)와 예측 확률을 확인할 수 있습니다.

### 7. 4개 분류 모델 성능 비교 및 해석 (`Test and Score`)

- **평가 조건**: `Random sampling` (`Repeat train/test: 10`, `Training set size: 66 %`, `Stratified`) 기준으로 `Logistic Regression`, `Random Forest`, `Gradient Boosting`, `Tree` 4개 모델의 생존(`Survived`) 예측 성능을 비교했습니다[cite: 16, 17, 18].
- **연결 확인 포인트**: `Select Columns`의 `Data` 출력이 `Test and Score`의 `Data` 입력에 연결되고, 각 모델 위젯의 `Learner` 출력이 `Test and Score`의 `Learner` 입력에 연결된 상태에서 `Evaluation results for target` 드롭다운(`(None, show average over classes)`, `0`, `1`)을 선택해 점수를 확인합니다[cite: 15, 16, 17, 18].

#### 주요 지표 의미 및 분석 해석

- **지표 해석 기준**:
  - **AUC**: 생존(`1`)과 사망(`0`)을 판별하는 종합 분별력 지표입니다.
  - **CA**: 전체 승객 중 실제 생존 여부를 정확히 맞힌 비율입니다.
  - **F1**: 정밀도(`Prec`)와 재현율(`Recall`)의 조화평균으로, 클래스 비율 차이(`0`: 549명, `1`: 342명)가 있는 이진 분류의 균형 성능을 나타냅니다.
  - **Prec / Recall / MCC**: 생존(`1`) 예측의 정밀도, 실제 생존자 포착률(`Recall`), 전반적 상관계수(`MCC`)를 나타냅니다.
- **결과 해석**:
  - **최고 성능 모델**: **Gradient Boosting**이 평균 기준(`AUC 0.849`, `CA 0.808`, `F1 0.804`, `MCC 0.585`)과 생존(`1`) 기준(`AUC 0.850`, `CA 0.808`, `F1 0.726`, `Prec 0.798`) 모두에서 가장 높은 성능을 기록했습니다.
  - **모델 간 차이**: 단일 의사결정나무(`Tree`)는 `AUC`가 `0.765~0.767` 수준인 반면, 앙상블 및 선형 모델(`Gradient Boosting`, `Random Forest`, `Logistic Regression`)은 `0.836~0.850`으로 일반화 성능이 뚜렷하게 높게 나타났습니다.
  - **클래스별 특성**: 사망(`0`) 기준 `F1`(`0.822~0.852`)에 비해 생존(`1`) 기준 `F1`(`0.693~0.726`)이 다소 낮게 나타나며, 생존(`1`) 재현율(`Recall`)은 `Random Forest`(`0.688`)가 가장 높고 정밀도(`Prec`)는 `Gradient Boosting`(`0.798`)이 가장 높습니다.

### 8. `Compare models by` 8개 평가 지표 의미 및 모델 비교 활용 포인트

`Test and Score` 창 하단 비교 행렬에서 **Compare models by** 드롭다운에 표시되는 8개 지표의 의미와 모델 선택 시 활용 기준을 위에서 아래 순서대로 정리했습니다[cite: 17].

| 순서 | 지표명 (`Compare models by`) | 의미 | 모델 비교 시 활용 포인트 |
| :---: | :--- | :--- | :--- |
| 1 | **Area under ROC curve** | 예측 확률 기준으로 긍정(`1`)을 부정(`0`)보다 높게 순위화하는 종합 분별력 지표 | 분류 임곗값(`0.5` 등)에 구애받지 않고 모델 전반의 판별 성능을 비교할 때 적합 |
| 2 | **Classification accuracy** | 전체 예측 중 실제 정답과 일치한 비율(정확도) | 두 클래스 비율이 비교적 균형 잡혔을 때 직관적인 전체 정답률을 비교할 때 활용 |
| 3 | **F1** | 정밀도(`Precision`)와 재현율(`Recall`)의 조화평균 | 클래스 건수 차이나 오탐·미탐 균형이 중요한 이진 분류에서 핵심 비교 지표로 활용 |
| 4 | **Precision** | 긍정(`1`)으로 예측한 사례 중 실제 긍정(`1`)인 비율 | 불필요한 긍정 오탐(거짓 양성, `False Positive`)을 줄이는 것이 중요할 때 확인 |
| 5 | **Recall** | 실제 긍정(`1`) 사례 중 모델이 긍정(`1`)으로 찾아낸 비율(민감도) | 실제 대상(예: 생존자)을 놓치지 않고 포착하는 것이 중요할 때 확인 |
| 6 | **Matthews correlation coefficient** | 혼동 행렬의 네 칸(`TP`, `TN`, `FP`, `FN`)을 모두 반영한 `-1`~`+1` 상관계수 지표 | 클래스 불균형이 있는 데이터에서도 편향 없이 전반적인 분류 품질을 비교할 때 유리 |
| 7 | **Specificity** | 실제 부정(`0`) 사례 중 모델이 부정(`0`)으로 정확히 판별한 비율(특이도) | 긍정(`1`) 포착률(`Recall`)과 함께 부정(`0`) 사례를 얼마나 잘 걸러내는지 확인할 때 활용 |
| 8 | **Logistic loss** | 예측 확률이 실제 정답과 얼마나 어긋나는지를 나타내는 확률 손실 지표 | 값이 **작을수록** 확률 예측이 잘 보정(calibration)되었음을 의미하며 확률 기반 비교에 유용 |

- **비교 행렬 읽는 법**: 행(row) 모델의 점수가 열(column) 모델의 점수보다 높을 확률을 나타내며, `Negligible diff.` 옵션을 켜면 두 모델의 점수 차이가 실질적으로 미미한 확률도 함께 확인할 수 있습니다.
- **수행평가 보고서** 에서는 이 8개 지표 중 AUC, Classification accuracy, F1 세 가지를 중심으로 비교하시면 결과를 가장 명확하게 전달할 수 있습니다.

### 9. `ROC Analysis` Target 값에 따른 축 의미 및 그래프 해석 포인트

[오렌지3](https://github.com/biolab/orange3)의 `ROC Analysis` 위젯에서 **Target**을 `1`(생존) 또는 `0`(사망)으로 설정했을 때 축의 의미와 곡선 해석 기준은 다음과 같습니다.

#### Target 값별 x축·y축 의미 비교

| Target 설정 | x축 (`FP Rate (1 - Specificity)`) 의미 | y축 (`TP Rate (Sensitivity)`) 의미 |
| :--- | :--- | :--- |
| **`1` (생존)** | 실제로는 생존하지 못한(`0`) 승객 중 **생존(`1`)으로 잘못 예측한 비율**(거짓 양성률 / 오탐률) | 실제 생존자(`1`) 중 **생존(`1`)으로 정확히 찾아낸 비율**(진양성률 / 재현율) |
| **`0` (사망)** | 실제로는 생존한(`1`) 승객 중 **사망(`0`)으로 잘못 예측한 비율**(거짓 양성률 / 오탐률) | 실제 사망자(`0`) 중 **사망(`0`)으로 정확히 찾아낸 비율**(진양성률 / 재현율) |

#### 그래프 해석 포인트

- **좌측 상단(`x = 0, y = 1`) 접근성**: 곡선이 좌측 위 모서리에 가까울수록 적은 오탐(`FP Rate`)으로 대상 클래스를 더 많이 찾아낸(`TP Rate`) 고성능 모델입니다.
- **기준선 및 모델 간 비교**: 점선 대각선(무작위 분류 기준)보다 위쪽에 위치할수록 판별력이 높으며, `Gradient Boosting`·`Random Forest` 곡선이 단일 `Tree` 곡선보다 상단에 위치해 일반화 성능 우위를 시각적으로 보여줍니다.
- **임곗값(`0.5` 부근) 라벨 의미**: `Default threshold (0.5) point` 옵션 활성화 시 곡선 위에 표시되는 소수점 값(`0.500`대)은 분류 확률 기준점(`0.5`) 인근의 임곗값 지점을 나타냅니다.

### 10. 혼동 행렬(`Confusion Matrix`) 기반 `Tree` vs `Random Forest` 모델 비교 분석

[오렌지3](https://github.com/biolab/orange3)의 `Confusion Matrix`(인스턴스 수 기준, 총 **891명**: 실제 사망 `0` **549명**, 실제 생존 `1` **342명**) 결과를 바탕으로 **Tree**와 **Random Forest** 모델의 예측 특성과 비교 핵심을 정리했습니다.

#### 1) 혼동 행렬 수치 및 수치적 해석

- **행(`Actual`)과 열(`Predicted`) 구조**: 행은 실제 클래스(`0`: 사망, `1`: 생존), 열은 모델의 예측 클래스(`0`: 사망, `1`: 생존)를 의미하며, 대각선(`Actual 0 & Pred 0`, `Actual 1 & Pred 1`)은 정답 건수, 비대각선(`Actual 0 & Pred 1`, `Actual 1 & Pred 0`)은 오분류 건수입니다[cite: 15, 16].

| 모델 | 실제 `0` → 예측 `0` (정답) | 실제 `0` → 예측 `1` (오탐) | 실제 `1` → 예측 `0` (미탐) | 실제 `1` → 예측 `1` (정답) | 전체 정답 / 오분류 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Tree** | 471 | 78 | 104 | 238 | **709** (79.57%) / **182** (20.43%) |
| **Random Forest** | **483** | **66** | **92** | **250** | **733** (82.27%) / **158** (17.73%) |

[cite: 15, 16]

- **`Tree` 수치 해석**: 전체 891명 중 **709명**(79.57%)을 정확히 맞히고 **182명**(20.43%)을 틀렸습니다[cite: 15]. 실제 사망자 549명 중 471명을 사망으로 맞히고 78명을 생존으로 잘못 예측했으며, 실제 생존자 342명 중 238명을 생존으로 찾아냈으나 **104명**(30.41%)을 사망으로 놓쳤습니다[cite: 15].
- **`Random Forest` 수치 해석**: 전체 891명 중 **733명**(82.27%)을 정확히 맞히고 **158명**(17.73%)만 틀렸습니다[cite: 16]. 실제 사망자 549명 중 483명을 정확히 판별하고 66명만 생존으로 오탐했으며, 실제 생존자 342명 중 250명을 찾아내고 **92명**(26.90%)을 놓쳤습니다[cite: 16].

#### 2) 주요 지표로 풀어본 모델별 특성

| 평가 관점 / 지표 | `Tree` | `Random Forest` | 산출 기준 및 해석 |
| :--- | :---: | :---: | :--- |
| **전체 정확도 (`Accuracy`)** | 79.57% (0.7957) | **82.27%** (0.8227) | `(정답0 + 정답1) / 891` — 전체 승객 중 정답 비율 |
| **오분류율 (`Error Rate`)** | 20.43% (0.2043) | **17.73%** (0.1773) | `(오탐 + 미탐) / 891` — 낮을수록 오분류가 적음 |
| **생존(`1`) 정밀도 (`Precision`)** | 75.32% (0.7532) | **79.11%** (0.7911) | `정답1 / (오탐 + 정답1)` — 생존 예측(`316명`) 중 실제 생존 비율 |
| **생존(`1`) 재현율 (`Recall`)** | 69.59% (0.6959) | **73.10%** (0.7310) | `정답1 / (미탐 + 정답1)` — 실제 생존자(`342명`) 중 포착 비율 |
| **생존(`1`) F1 점수** | 0.7234 | **0.7599** | `2 * Prec * Recall / (Prec + Recall)` — 생존 예측 균형 지표 |
| **사망(`0`) 재현율 / 특이도** | 85.79% (0.8579) | **87.98%** (0.8798) | `정답0 / (정답0 + 오탐)` — 실제 사망자(`549명`) 판별 비율 |


- **`Tree` 특성**: 단일 의사결정나무 구조 특성상 해석은 직관적이지만, 생존(`1`) 재현율(69.59%)과 정확도(79.57%)가 `Random Forest`보다 낮고 생존자를 놓치는 미탐(104명) 비중이 비교적 큽니다.
- **`Random Forest` 특성**: 다수의 트리를 앙상블해 과적합을 줄인 결과, 생존(`1`) 정밀도(79.11%)와 재현율(73.10%)이 동시에 상승하며 전반적인 분류 안정성과 정확도(82.27%)가 높아졌습니다[cite: 16].

#### 3) 두 모델 비교 핵심 포인트

- **전체 정답 인원 +24명 증가 및 오분류 -24명 감소**: `Random Forest`는 `Tree` 대비 정답 사례가 **709명 → 733명**으로 늘고, 오분류 사례가 **182명 → 158명**으로 줄었습니다.
- **생존자(`1`) 포착 및 오탐 동시 개선**: 실제 생존자 중 찾아낸 인원이 **238명 → 250명**(+12명)으로 늘었고, 사망자를 생존으로 잘못 예측한 오탐도 **78명 → 66명**(-12명)으로 줄어 생존(`1`) F1 점수가 **0.7234 → 0.7599**로 향상되었습니다.
- **일관된 예측 총량 속 질적 개선**: 두 모델 모두 사망(`0`) 예측 합계 **575명**, 생존(`1`) 예측 합계 **316명**으로 예측 건수 총량은 같지만, `Random Forest`가 실제 정답과 더 잘 일치하도록 배분한 점이 핵심 차이입니다.
